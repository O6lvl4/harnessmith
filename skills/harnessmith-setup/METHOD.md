# harnessmith の考え方

エージェントに仕事を任せるハーネスを作り、点数で比べながら育てる。作業エージェントには解答を見せない。構成をいじる前に、測る側が正しいかを先に確かめる。

## 使える仕事

次の 3 つがそろう仕事に使う。そろわない仕事（1 回きりの移行、正解のない企画）には使わない。

- 同じ仕事を、何度もやり直せる（1 回が数十分〜数時間、数千円）
- 出来を点数にできる（正解、手本、合格の基準、テストのどれかがある）
- 正解を作業エージェントから隠せる

| 仕事の例 | 正解にあたるもの | 採点 |
| --- | --- | --- |
| 資料から成果物を作る（設計、図、文書） | 手本の成果物 | 採点表の項目ごとに「ある・一部・ない」 |
| 仕様書からの実装 | 受け入れテスト（作業役には見せない） | コマンド：通ったテストの割合 |
| 既存コードの移行・書き換え | 元の実装のふるまい | コマンド：同じ入力への応答が一致する割合 |
| 調査・レビュー | 既知の不具合の一覧 | 採点表：見つけた割合 |

## 役割を分ける

| 役割 | 読めるもの | 読めないもの |
| --- | --- | --- |
| 作業役 | 資料 | 解答、採点表、ベンチ、ほかの試行 |
| 採点役（判定者 2 体、またはコマンド） | 成果物、採点表 | — |
| 振り返り役 | 資料、成果物、部分ごとの点 | 解答、採点表、項目ごとの結果 |
| 進行役（人、またはスキルを動かす Claude） | 部分ごとの点、件数、番号 | 解答、採点表、項目ごとの結果 |

解答を見た者が指示を書くと、そこから解答が漏れ、点数の意味がなくなる。進行役が中身を知る必要があるときは、別のエージェントに調べさせ、番号と件数だけを受け取る。

## 点検 4 つ（構成をいじる前に）

| 点検 | 飛ばすと起きること |
| --- | --- |
| 採点表を、書いた者とは別の目で解答と照らす | 写し違いで、同じ成果物の点が動く。そのぶれを構成のせいだと読む |
| 判定の基準（「一部」と「ない」の境目、順序や向きの扱い）を書く | 判定者の判定が割れ、点が安定しない |
| 比べる相手が、何を読んで作られたかを確かめる | 解答を見て直した版を基準にし、解答なしの構成に届かない線を追わせる |
| 何も足さない構成を 3 回以上回し、ぶれの幅を測る | ぶれと同じ大きさの差を「効いた・効かない」と読む |

## 回し方

1. 素の構成の、点の低い部分だけを見る。十分な部分には何も足さない
2. 変更は 1 つずつ。案は振り返り役に出させる
3. 候補は 2 回以上回し、平均で親と比べる。ぶれの幅を超えた差だけを採る
4. 3 世代続けて上がらなければ止まり、構成ではなく点検 4 つをやり直す

## これまでに分かったこと

- 失う時間の大半は、エージェントではなく測る側の誤りから来る
- 素の構成は強い。段取り（手分け、道具作り、動作確認）は任せられる
- 効くのは「課題文の読み方が割れるところを、どちらに読むか決める」指示。工程（見直し、対応表、別の目）を足す指示は効かず、ほかの部分を下げる
- 解答を知って書いた指示で回した試行は、分けて記録し、成果に数えない（`trial --unblind`）

## 人に見せるときに添える 4 つ

- 何と比べた点か（比べる相手が、何を読んで作られたか）
- 何回回した点か、ぶれの幅はいくつか
- 採点表は誰が書き、誰が点検したか
- 解答を見ずに届いた点と、見て届いた点の区別
