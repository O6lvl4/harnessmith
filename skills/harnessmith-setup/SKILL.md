# harnessmith-setup

harnessmith は、エージェントに仕事を任せるハーネスを作り、点数で育てるための道具である。このスキルは、ベンチを作り、構成をいじる前の点検 4 つを通すところまでを行う。考え方は同じフォルダの `METHOD.md` にある。最初に読む。

道具は `tool/harnessmith.py`（このスキルのフォルダにある）。`init` がベンチの `tool/` に写すので、ベンチができたあとはベンチの写しを使う。

## 守ること

- **進行役（あなた）は、解答と採点表を読まない。** `~/.harnessmith/<名前>/private/` の中、各試行の `score.json`・`score.md`・`judge/` を、Read でも cat でも開かない。中身を知る必要があるときは `draft`・`audit` に任せ、返ってくる番号と件数だけを使う。
- 利用者が解答を会話に貼ろうとしたら、貼らずにファイルで `private/` に置いてもらう。貼られてしまったら、その旨を伝え、このセッションでは構成（`comp/`）を書かないことにする。
- 資料に解答が混ざっていないかは、利用者に確かめてもらう。自分で解答と突き合わせない。

## 1. 仕事が向いているかを確かめる

利用者に次を聞く。分かっているものは聞かない。

- 何の仕事か。作業エージェントに渡す資料はどこにあるか
- 正解にあたるものは何か（手本の成果物、隠しテスト、元の実装のふるまい）。それは作業エージェントから隠せるか
- 成果物は何で、どこに置かせるか
- 1 回の上限（時間・USD）と、全体の予算
- 比べる相手（人が作った版など）はあるか。あるなら、それは解答を見て作られたか

何度もやり直せない、点数にできない、正解を隠せない、のどれかなら、harnessmith には向かないと伝えて止める。

## 2. ベンチを作る

```sh
python3 <このスキルのフォルダ>/tool/harnessmith.py init <ベンチを置くフォルダ> --name <名前> --deliverable <成果物のフォルダ名>
```

ベンチは、利用者のリポジトリの中に置く（構成・台帳・振り返りを commit するため）。資料・解答・試行の記録は `~/.harnessmith/<名前>/` に置かれ、commit されない。

続けて次をする。

- 資料を `~/.harnessmith/<名前>/materials/` に置く。課題文もここに入れる。**解答を含めない。**
- 解答を `~/.harnessmith/<名前>/private/` に、利用者に置いてもらう。
- `comp/bare/PROMPT.md` を直す。書くのは、課題の在処、成果物の置き場所、無人で行われること、人が後でやるので手を出さないこと（push、外部への投稿など）だけ。解き方は書かない。
- `harnessmith.json` を直す。`goal`（振り返り役に渡すゴールの文）、時間と予算、`scorers`。

採点の方法は 2 つあり、併用できる。

| `scorers` の書き方 | 使うとき |
| --- | --- |
| `{"type": "rubric"}` | 手本にある項目を、成果物が拾えているかで測る。判定者 2 体が項目ごとに判定する |
| `{"type": "command", "part": "<名前>", "cmd": "<コマンド>"}` | テストや照合で測る。成果物のフォルダで実行され、出力の最後の行（0〜100）が点になる。数字がなければ終了コード 0 で 100 点。隠しテストは `private/` に置き、`$HARNESSMITH_PRIVATE` で参照する |

一度だけ、隔離用の設定でログインしてもらう。`! CLAUDE_CONFIG_DIR=~/.harnessmith/config claude` を起動して `/login` し、抜ける。

## 3. 採点表を書かせ、別の目で点検させる（rubric を使うとき）

```sh
python3 tool/harnessmith.py draft --parts "<何を採点したいか。部分の分け方と、グループ（担い手など）>"
python3 tool/harnessmith.py audit      # 直しが 0 件になるまで繰り返す
```

- `--parts` には、利用者から聞いた「見たい観点」を書く。解答の中身は書かない（知らないはず）。
- `audit` が「決められなかった」と返した項目は、利用者に `private/audit.md` を見て決めてもらう。
- 採点表を直すと、それまでの試行は数に入らなくなる（採点表が違う点は比べられない）。`score <試行のフォルダ>` で採点し直せるが、台帳には `trial` で回し直した分だけが載る。

## 4. 比べる相手を採点する（あれば）

```sh
python3 tool/harnessmith.py reference <その版の成果物のフォルダ> --name <名前> \
  --saw-answer yes|no|unknown --provenance "<何を読んで、誰がいつ作ったか。確かめた根拠>"
```

`--saw-answer` は、コミットや会話の記録で確かめてから書く。確かめられなければ `unknown`。目標にしてよいのは `no` の版だけで、`harnessmith.json` に `"target_from": "<名前>"` と書くと「その版から tolerance 以内」が目標になる。比べる相手がなければ、`"targets": {"<部分>": <点>}` で直接決めるか、目標を置かずに回す。

## 5. 素の構成を 3 回回す

```sh
python3 tool/harnessmith.py trial -c bare -n 3
```

時間がかかるので、バックグラウンドで実行する。最初の 1 回が終わったら、`~/.harnessmith/<名前>/runs/<試行>/events.jsonl` を見て、作業エージェントが資料を読めているか、成果物を決めた場所に置いたかを確かめる。採点されずに終わったら、`leak.txt`・`stderr.log` を見て直す。

## 6. 点検を通して、報告する

```sh
python3 tool/harnessmith.py check
python3 tool/harnessmith.py status
```

4 つとも ○ になったら終わり。利用者に、素の構成の点（平均と幅）、ぶれの幅、使った額、点の低い部分を伝える。素の構成で十分な点が出ていれば、「これ以上の手当ては要らない」と伝える。それも結論である。

続きは `/harnessmith-run`。
