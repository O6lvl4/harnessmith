# harnessmith-status

ベンチ（`harnessmith.json` のあるフォルダ）で、次を実行して読む。ベンチがどこか分からなければ、`harnessmith.json` を探すか、利用者に聞く。

```sh
python3 tool/harnessmith.py status          # 人が読む形
python3 tool/harnessmith.py status --json   # 数字を使うとき
```

解答と採点表（`~/.harnessmith/<名前>/private/`、各試行の `score.json`・`score.md`・`judge/`）は開かない。

## 伝えること

1. **いまの結論を 1〜2 行で。** 採用中の構成と、その点（平均と最小〜最大）。目標があれば、届いたか。
2. **点検に × があれば、最初に言う。** × があるあいだの点数は、比べる根拠にならない。
3. **構成ごとの表。** 構成、回数、部分ごとの平均（幅）、採否。差は、ぶれの幅と並べて書く。ぶれの幅より小さい差を「上がった・下がった」と書かない。
4. **使った額と、止める条件までの残り。**
5. **次の一手を 1 つ。** 点検を通す／次の世代を回す（harnessmith-run）／測る側を点検し直す／ここで終える、のどれか。

## 人に見せる形にするとき

報告やスライドにするときは、点数に次の 4 つを必ず添える。`status` の出力と台帳（`ledger.jsonl` の `reference`・`audit`・`trial` の行）から拾える。

- 何と比べた点か。比べる相手が、何を読んで作られたか（`reference` の `saw_answer` と `provenance`）
- 何回回した点か、ぶれの幅はいくつか
- 採点表は誰が書き、誰が点検したか（`rubric`・`audit` の行。直した件数も）
- 解答を見ずに届いた点と、見て届いた点（`--unblind` の試行）の区別

条件を外した試行と、採点表が変わる前の試行は、成果の数字に混ぜない。
